Round 5 source audit (code-only, 2026-10-15)

T1 GMS:
- Bcore exposes BlackBoxCore.isSupportGms(), installGms(userId), isInstallGms(userId), and
  hasGmsTraces(userId).
- GmsCore.installGApps() imports the phone packages in its GOOGLE_SERVICE/GOOGLE_APP sets;
  those sets include com.google.android.gms, com.google.android.gsf, and com.android.vending.
- EngineBridge now calls isSupportGms() before installGms(0), logs the InstallResult fields,
  and continues to launch the requested guest. The app manifest has three explicit <queries>
  package entries and does not use QUERY_ALL_PACKAGES.

T2 sizing:
- GuestPresentationHost.beforeMainActivityOnCreate now sets densityDpi=320,
  screenWidthDp=640, screenHeightDp=360, landscape, and the window attributes to 1280x720
  before the guest lifecycle reaches onCreate/setContentView.
- BlackBox's ignored vendor source now dispatches this callback from its instrumentation
  before the guest onCreate. Android still rejected applyOverrideConfiguration because
  resources had already been initialized during attach, so the host uses a public
  updateConfiguration fallback. The post-resume diagnostic remains in place.

T4 resolver:
- EngineBridge now logs host and virtual activity records, host split names, and considers
  an activity-alias target component before reporting VIRTUAL_LAUNCH_COMPONENT_MISSING.
- The package audit runs after virtual import, so it can compare the imported virtual
  activity records with the host's split/alias records.
- Phone package and browser results are recorded in `round5_phone_results.txt`; the source
  audit itself remains code-only.

The engine callback patch is reproduced by `android/engine/fetch-source.sh`; it is not a
direct edit to the ignored vendor tree.
